# PRD: 개발자 프로필 웹사이트 (DemoPort)

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 (v0.1) |
| 프로젝트명 | DemoPort |
| 개발자(사이트 주인) | 테스트 |
| 연락처 | cookietest@aaa.test |
| 주 개발 분야 | 바이브코딩, Python, HTML5 |
| 저장 위치 | `DemoPort/prd.md` |

> 이 문서는 사이트를 만들기 전에 "무엇을, 누구를 위해, 어디까지" 만들지 정하는 기획서다.
> 아직 정해지지 않은 내용(소개 문구, 프로젝트 목록, 배포 위치 등)은 지어내지 않고
> **[미정]** 으로 표시했으며, 마지막의 "열린 질문"에 모아 두었다.

## 1. 배경과 목적

### 1.1 배경
개발자 "테스트"는 Python과 HTML5를 주력으로 하는 개발자다. 이력서나 메신저로 링크를 하나씩 보내는 대신,
**주소 하나로 자신이 누구이고 무엇을 할 수 있으며 어떻게 연락하면 되는지** 보여 주는 개인 웹사이트가 필요하다.

### 1.2 목적
- 방문자가 **30초 안에** "이 사람은 Python/HTML5 개발자이고, 이런 결과물을 만들었구나"를 이해하게 한다.
- 관심이 생긴 방문자가 **한 번의 클릭으로** 이메일(cookietest@aaa.xtr)을 보낼 수 있게 한다.
- 사이트 자체가 HTML5 실력을 보여 주는 **결과물**이 되게 한다(시맨틱 마크업, 접근성, 성능).

### 1.3 성공 기준
| 지표 | 목표 | 확인 방법 |
|---|---|---|
| Lighthouse Performance | 90점 이상 | Chrome/Edge Lighthouse (모바일 기준) |
| Lighthouse Accessibility | 95점 이상 | 동일 |
| Lighthouse SEO / Best Practices | 각 90점 이상 | 동일 |
| 첫 화면 표시(LCP) | 2.5초 이내 | Lighthouse / PageSpeed |
| 페이지 용량(이미지 제외) | 200KB 이하 | 개발자 도구 Network 탭 |
| 연락처 노출 | 스크롤 없이 또는 한 번의 이동으로 이메일에 도달 | 수동 확인 |

## 2. 대상 사용자

| 구분 | 누구 | 원하는 것 | 사이트가 해 줘야 할 것 |
|---|---|---|---|
| 채용 담당자 / 면접관 | 개발자를 평가하는 사람 | 기술 스택, 결과물, 연락 방법을 빠르게 확인 | 첫 화면에서 정체성과 스택, 프로젝트 링크 제공 |
| 협업·외주 의뢰인 | 개발자를 찾는 사람 | 무슨 일을 맡길 수 있는지, 연락 방법 | 할 수 있는 일과 연락처를 명확히 |
| 동료 개발자 | 같은 분야의 사람 | 코드와 작업 방식 | 프로젝트별 저장소 링크와 사용 기술 |

주요 사용 환경: 데스크톱 브라우저와 스마트폰 브라우저(메신저로 링크를 받아 여는 경우가 많음).
따라서 **모바일에서 먼저 잘 보이는 것**이 중요하다.

## 3. 범위

### 3.1 v1에 포함 (In scope)
- 한 페이지(Single Page)로 구성된 정적 웹사이트
- 섹션: 히어로(첫 화면) / 소개 / 기술 / 프로젝트 / 연락처 / 푸터
- 반응형 레이아웃, 라이트/다크 테마(시스템 설정 따름)
- 접근성(키보드 조작, 스크린리더, 색 대비), 기본 SEO 메타 태그
- 이메일 링크(`mailto:`)와 "이메일 주소 복사" 버튼

### 3.2 v1에서 제외 (Out of scope)
- 로그인, 회원 기능, 관리자 화면
- 서버에 저장되는 문의 폼(→ 2단계에서 검토, 6장 참고)
- 블로그/글쓰기 기능
- 다국어(영어 등) 지원 — 한국어 단일 언어로 시작
- 방문자 추적/분석 도구(트래커) — 개인정보와 로딩 속도를 위해 넣지 않음

## 4. 기능 요구사항

우선순위: **P0** = 없으면 출시 불가 / **P1** = 넣는 것이 좋음 / **P2** = 여유가 있을 때

### 4.1 상단 내비게이션 (P0)
- FR-1. 상단에 고정된 메뉴: 소개 · 기술 · 프로젝트 · 연락처. 클릭하면 해당 섹션으로 부드럽게 이동한다.
- FR-2. 모바일에서는 메뉴가 접히는 버튼(햄버거)으로 바뀐다. 키보드로도 열고 닫을 수 있다.
- FR-3. 현재 보고 있는 섹션의 메뉴 항목이 강조된다. (P1)

### 4.2 히어로 섹션 (P0)
- FR-4. 개발자 이름 **테스트**, 한 줄 소개, 주 분야(**Python · HTML5**)를 가장 크게 보여 준다.
- FR-5. 행동 버튼 2개: **[프로젝트 보기]**(프로젝트 섹션으로 이동), **[이메일 보내기]**(`mailto:cookietest@aaa.xtr`).
- 한 줄 소개 문구: **[미정]**

### 4.3 소개 섹션 (P0)
- FR-6. 개발자 소개 2~4문장. 어떤 일을 하고 어떤 문제를 좋아하는지를 담는다.
- FR-7. 프로필 사진 또는 일러스트를 넣을 수 있는 자리를 둔다. 사진이 없으면 이니셜 아바타("테")로 대체한다. (P1)
- 소개 문구, 사진 제공 여부: **[미정]**

### 4.4 기술 섹션 (P0)
- FR-8. 주 기술 **Python**, **HTML5**를 가장 먼저, 크게 보여 준다.
- FR-9. 각 기술마다 "무엇을 만들 때 어떻게 써 봤는지"를 한 줄로 적는다. (예: Python → 자동화 스크립트·게임·데이터 처리 등 **실제 경험에 맞게 작성**)
- FR-10. 기술 수준을 퍼센트 막대로 표시하지 **않는다**. 수치는 근거가 없고 오해를 부르므로, 태그와 한 줄 설명으로 표현한다.
- FR-11. 보조 기술(CSS3, JavaScript, Git 등)은 작은 태그로 추가할 수 있다. 어떤 것을 넣을지는 **[미정]**

### 4.5 프로젝트 섹션 (P0)
- FR-12. 카드 형태로 3~6개 프로젝트를 나열한다. 카드 구성: 제목 · 한 줄 설명 · 사용 기술 태그 · 링크(저장소 / 데모).
- FR-13. 링크는 새 탭에서 열리며(`rel="noopener noreferrer"`), 링크 목적이 텍스트로 분명해야 한다("자세히"만 쓰지 않는다).
- FR-14. 카드에 스크린샷을 넣을 수 있다. 이미지에는 대체 텍스트(`alt`)를 반드시 넣는다. (P1)
- FR-15. 프로젝트가 늘어도 데이터(제목, 설명, 링크)만 바꾸면 되도록 카드 구조를 반복 가능한 형태로 만든다.
- 실제 프로젝트 목록: **[미정]**

### 4.6 연락처 섹션 (P0)
- FR-16. 이메일 **cookietest@aaa.xtr** 를 텍스트와 `mailto:` 링크로 보여 준다.
- FR-17. **[주소 복사]** 버튼: 누르면 클립보드에 복사되고 "복사되었습니다"가 화면에 표시된다(스크린리더도 읽을 수 있게 `aria-live`). 복사 기능을 못 쓰는 환경에서는 링크만 동작해도 된다.
- FR-18. GitHub 등 외부 프로필 링크 자리를 둔다. 계정 정보: **[미정]**

### 4.7 푸터 (P0)
- FR-19. 저작권 표기(© 연도 테스트), "맨 위로" 링크.

### 4.8 테마 (P1)
- FR-20. 기본은 시스템 설정(`prefers-color-scheme`)을 따르고, 수동 전환 버튼을 둔다. 선택은 브라우저에 기억한다(저장소를 못 써도 사이트는 정상 동작).

## 5. 비기능 요구사항

### 5.1 성능
- 프레임워크 없이 HTML/CSS/최소한의 JavaScript만 사용한다.
- 외부 스크립트·트래커를 쓰지 않는다. 폰트는 시스템 폰트를 우선 사용한다(외부 폰트를 쓰면 로딩과 개인정보 이슈가 생김).
- 이미지는 적절한 크기로 줄이고 `loading="lazy"`, 가로·세로 크기 지정으로 화면 밀림을 막는다.

### 5.2 접근성 (WCAG 2.1 AA 지향)
- 시맨틱 요소 사용: `header`, `nav`, `main`, `section`, `article`, `footer`, 제목 계층(`h1`→`h2`→`h3`)을 건너뛰지 않는다.
- 모든 기능을 키보드만으로 사용 가능, 포커스 표시가 분명해야 한다.
- 본문 텍스트 색 대비 4.5:1 이상(라이트/다크 모두).
- "본문으로 건너뛰기" 링크 제공.
- 애니메이션은 `prefers-reduced-motion` 설정을 존중한다(움직임 줄이기 선택 시 부드러운 스크롤·전환 비활성화).

### 5.3 반응형
- 지원 폭: 320px ~ 1440px 이상. 가로 스크롤이 생기지 않아야 한다.
- 중단점(예시): 모바일 ~ 640px / 태블릿 ~ 1024px / 데스크톱 1024px 초과.

### 5.4 SEO·공유
- `<title>`, `meta description`, `lang="ko"`, Open Graph(제목·설명·대표 이미지) 태그.
- 파비콘, 대표 이미지(OG 이미지) 1장. 제작 여부: **[미정]**

### 5.5 호환성
- 최신 Chrome, Edge, Firefox, Safari(iOS 포함)의 최신 2개 버전.
- JavaScript가 꺼져 있어도 **내용은 모두 읽히고 이메일 링크는 동작**해야 한다(점진적 향상). JS는 메뉴 접기·복사 버튼·테마 전환에만 사용한다.

### 5.6 보안·개인정보
- 외부 서버로 데이터를 보내는 기능이 없다(v1).
- 이메일 주소가 공개 페이지에 그대로 노출되므로 스팸 수신 가능성이 있다(7장 위험 참고).

## 6. 기술 방향

### 6.1 v1 기술 스택
| 영역 | 선택 | 이유 |
|---|---|---|
| 마크업 | HTML5 (시맨틱) | 주력 분야를 그대로 보여 줌 |
| 스타일 | CSS3 (CSS 변수, Flexbox/Grid, 미디어 쿼리) | 프레임워크 없이도 반응형·다크 모드 구현 가능 |
| 동작 | Vanilla JavaScript (필요 최소한) | 빌드 도구 없이 파일만 열어도 실행 |
| 배포 | 정적 호스팅 (GitHub Pages / Netlify 등 **[미정]**) | 무료, 서버 관리 불필요 |

### 6.2 Python의 역할
주력 분야인 Python은 v1 화면에는 직접 쓰이지 않는다. 대신 다음처럼 확장할 수 있다.
- **(2단계 후보 A)** 프로젝트 목록을 `projects.json`(또는 YAML)에 두고, Python 스크립트로 HTML 카드를 생성하는 **정적 사이트 생성기**.
- **(2단계 후보 B)** Flask/FastAPI 등으로 **문의 폼 백엔드**를 만들어 메일 발송.
- 두 방식 모두 v1 이후에 필요해지면 도입한다. 지금은 단순함(수정 → 저장 → 새로고침)을 우선한다.

### 6.3 폴더 구조 (예정)
```
DemoPort/
├─ prd.md                ← 이 문서
├─ index.html            ← 단일 페이지
├─ css/
│  └─ style.css
├─ js/
│  └─ main.js
└─ assets/
   ├─ favicon.svg
   ├─ og-image.png       (대표 이미지, 선택)
   └─ projects/          (프로젝트 스크린샷, 선택)
```

- [ ] 이름 "테스트", 이메일 "cookietest@aaa.xtr"이 정확히 표기되고 `mailto:` 링크가 메일 프로그램을 연다
- [ ] 주 분야 Python, HTML5가 첫 화면과 기술 섹션에 모두 나타난다
- [ ] 모든 섹션 메뉴가 올바른 위치로 이동한다
- [ ] 320px 폭에서 가로 스크롤이 없고 글자가 잘리지 않는다
- [ ] 키보드(Tab, Enter, Esc)만으로 메뉴·버튼·링크를 모두 사용할 수 있고 포커스가 보인다
- [ ] 라이트/다크 양쪽에서 글자 대비가 충분하다
- [ ] 이미지에 `alt`가 있고, 장식용 이미지는 빈 `alt=""`이다
- [ ] JavaScript를 끈 상태에서 모든 내용을 읽을 수 있다
- [ ] Lighthouse 목표 점수(1.3장)를 충족한다
- [ ] 자리표시 문구(`[미정]`, 예시 텍스트)가 남아 있지 않다
